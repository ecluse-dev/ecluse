# P2-89 — Mesure du NER candidat 1 sur les corpus flous

Mesure seulement, rien n'est corrigé. Exécutée le 8 novembre 2026 sur le PC
du mainteneur (machine de référence, P2-87 : Windows, CPU), avec
`bench/ner_predict.py` (protocole `bench/ner_predictions.md`).

- Modèle : `Anonym-IA/V2-camembert-ner-pii-french`, téléchargé depuis
  Hugging Face ; pipeline `token-classification`, `aggregation_strategy=simple`,
  `stride=64`, **aucun seuil de confiance** (tous les spans rendus).
- Environnement : Python 3.14, torch 2.15.0 (CPU), `main` au commit
  `e64caa9`. Corpus flous régénérés (`--n 400 --seed 42`), mêmes effectifs
  que `bench/ETAT.md`.
- « int8 » : quantification dynamique PyTorch des couches linéaires
  (`quantize_dynamic`), **pas** l'int8 ONNX qui serait livré.

## 1. Labels du modèle

Tous les labels du § 3 se retrouvent (`NOM_PERSONNE`, `PRENOM_PERSONNE`,
`NUMERO_VOIE`, `NOM_VOIE`, `CODE_POSTAL`, `VILLE`, `TELEPHONE`, `EMAIL`,
`NOM_SOCIETE`…). Il existe un label `DOB` mais il ne contient pas
« NAISSANCE » : le script l'a gardé tel quel au lieu de le ranger en
`date_naissance`. Effet nul sur la fuite au caractère (tout span compte), réel
sur les colonnes strictes `date_naissance` du NER (0 %).

## 5. Lecture contre le critère GO/STOP (P2-01 § 4, seuils validés en P2-87)

- **A. Gain sur l'adversarial ≥ 5 points** : 9,3 % → 6,0 %, soit
  **3,3 points**, et cela à rappel maximal (aucun seuil de confiance) :
  **non atteint** (condition STOP n° 6). Noms et adresses ne remontent pas.
  Sur le réaliste, le gain ne porte que sur la civilité, laissée en clair
  volontairement.
- **C. Témoin ≤ 1 %** : 46,5 % (FP32), 3,8 % (int8) : **non atteint**.
- **E. Latence ≤ 2 s** : atteinte (1,7 s). **Taille ≤ 300 Mo** : 445 Mo en
  FP32 ; taille int8 non mesurée.
- **B, D, F** : non évalués ici (intégration, licence).

Deux conditions de A à D ne sont pas remplies : la proposition de la mesure
est **STOP** pour ce modèle. La décision appartient au mainteneur (P2-90).

## 6. Ce qui reste incertain

- Un seuil de confiance (corpus de calibration, condition C) réduirait les
  faux positifs, mais aussi le gain, déjà sous le seuil à rappel maximal.
- La quantification dynamique PyTorch dégrade fortement le modèle (réaliste :
  NER seul presque muet) ; l'int8 ONNX n'a pas été mesuré. Sans effet sur la
  conclusion : la version FP32 ne passe déjà pas A ni C.
- Le gain réel est concentré sur les noms de l'adversarial hors civilité
  (974 → 289 caractères) : c'est là que les heuristiques ont leurs angles
  morts. Un autre candidat (candidat 2 de P2-86) pourrait être mesuré avec le
  même script.
