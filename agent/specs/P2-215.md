# P2-215 — Écritures de communes hors référentiel : ce que le « nom exact » ne couvre pas

Type `spec` : aucune ligne de code de production. La mesure est faite par un
script hors `lib/`, versionné : `bench/ecritures_hors_referentiel.py` (et ses
tests). Rédigée le 16 novembre 2026 sur `main` au commit `bd7d24b`, graine 42.
Les décisions restent au mainteneur.

## La question

La règle « nom exact du référentiel » (décision du 16 novembre, tâche P2-214)
porte une commune en capitales, sans « CEDEX », jusqu'à la fin de son nom
quand ce nom est écrit comme le référentiel l'écrit. Le « 0 » simulé par
P2-206 est vrai par construction : le balayage écrit les noms du référentiel,
la règle les lit. Que reste-t-il quand la commune est écrite **autrement** ?

## Ce qui est mesuré, et par quel chemin

- **Population.** Les 261 communes pour lesquelles la règle est la seule
  protection : celles que le motif d'`AdresseDetector` ne lit pas en entier
  (formes A, C et D de `agent/specs/P2-205.md` : 251 de cinq mots ou plus, 9 à
  parenthèse ou tiret isolé, « LES PLACES »). **Les 34 614 autres communes ne
  sont pas concernées** : pour un nom de quatre mots au plus, le motif ne
  regarde pas l'orthographe (un mot à majuscule lui suffit), une faute ou un
  « ST » n'y change rien. La forme B (mot neutre en tête) est hors de la règle.
- **Écritures.** Une adresse par commune et par variante applicable, tout en
  capitales, sans CEDEX, code postal fabriqué : 1 348 adresses.
- **Chemin.** `Ecluse.redact` (ce que reçoit le LLM, prédictions de
  `run_redact_bench.dart`), **plus** l'étendue qu'une règle candidate
  ajouterait (union, comme `regles_candidates_communes.py`). Les règles sont
  simulées : `resolveOverlaps` n'est pas rejoué, les chiffres sont un ordre de
  grandeur. « En clair » = au moins un caractère non blanc de l'adresse sous
  aucune détection.
- **État du code.** `main` ne contient pas encore la règle (P2-214 est en PR,
  #432). La colonne « nom exact » ci-dessous est donc elle aussi simulée.

## Résultat : la part que le nom exact ne couvre pas

Adresses en partie en clair. Les chiffres sont les mêmes avec la table complète
(34 875 communes, 32 587 noms distincts) et avec la table réduite aux 261 noms
(celle de #432).

| Écriture | Adresses | `Ecluse.redact` seul | + nom exact | + normalisation (option 1) | + une lettre d'écart (option 2) |
|---|---:|---:|---:|---:|---:|
| référence (forme postale), contrôle | 261 | 140 | **0** | 0 | 0 |
| accents gardés (« CHÂTEAU CHINON (VILLE) »), contrôle | 80 | 46 | **0** | 0 | 0 |
| « ST », « STE » pour SAINT, SAINTE | 170 | 66 | **66** | 0 | 0 |
| apostrophe perdue, mots collés (« DAURELLE ») | 69 | 9 | **9** | 0 | 0 |
| tiret perdu, mots collés (« MORINEN BRIE ») | 246 | 33 | **33** | 0 | 0 |
| une lettre fautive | 261 | 141 | **141** | 141 | 0 |
| une lettre omise | 261 | 139 | **139** | 139 | 0 |
| **cinq écritures hors référentiel** | **1 007** | **388** | **388** | **280** | **0** |

Lecture.

1. **Accent perdu ou gardé : couvert.** La règle compare sans accent ; les deux
   contrôles sont à 0.
2. **Apostrophe ou tiret remplacés par une espace : couvert** (c'est la forme
   postale elle-même, ligne « référence »).
3. **Tout le reste n'est pas couvert du tout** : sur les cinq écritures hors
   référentiel, le nom exact ne retire **aucune** des 388 adresses en défaut
   (388 → 388). Un nom mal écrit retombe exactement sur la limite d'avant
   P2-214 : la fin du nom en clair, le code postal et le début masqués.
4. La part touchée dépend de l'écriture : 66 / 170 pour « ST » (39 %), autour
   de 54 % pour une lettre fautive ou omise, 13 % pour un séparateur collé.
   Le reste est déjà masqué par le motif, faute ou pas (nom en quatre mots
   ou moins une fois collé, ou fin de nom prise par un autre détecteur).

**Ce que ces chiffres ne disent pas** : une fréquence. Personne n'a compté
combien d'adresses réelles écrivent « ST » ou portent une faute ; le corpus
suppose une faute par nom, tirée au hasard. Deux fautes dans le même nom, les
abréviations autres que « ST » et « STE » (« S/ » pour « SUR », « STS »), les
anciens noms de communes et les lieux-dits ne sont pas mesurés.

## Options

### 1. Normaliser avant de comparer

« ST » et « STE » deviennent « SAINT » et « SAINTE », puis le nom et le texte
sont comparés **collés** (espaces retirées des deux côtés), ce qui absorbe une
apostrophe ou un tiret perdus sans espace.

- Gain mesuré : 388 → 280 ; les trois écritures « ST », apostrophe collée et
  tiret collé passent à 0. Les fautes de lettre restent (280).
- Risque de faux positifs mesuré (lignes sans adresse des témoins, texte mis
  en capitales, borne haute) : **aucune ligne de plus** que le nom exact, sur
  les deux tables (voir le tableau plus bas).
- Risque non mesuré : la comparaison collée peut rapprocher deux suites de
  mots différentes qui donnent les mêmes lettres. Avec des noms de cinq mots
  ou plus, il faudrait une phrase ordinaire qui épelle un nom entier.
- Coût de réalisation : faible. Une seconde clé par nom dans la table, la
  même normalisation côté texte.

### 2. Distance d'édition bornée à une lettre

En plus de l'option 1, une lettre d'écart est tolérée (substitution, lettre en
trop ou en moins) entre le texte collé et un nom collé d'au moins huit lettres.

- Gain mesuré : 388 → **0** sur le corpus (une seule faute par nom, par
  construction).
- **Le risque dépend entièrement de la table.**

| Lignes sans adresse où la règle ajouterait un masquage | Lignes | nom exact | option 1 | option 2 (≥ 8 lettres) | option 2 (≥ 4 lettres) |
|---|---:|---:|---:|---:|---:|
| **Table réduite (261 noms)** | | | | | |
| témoin cinq chiffres (P2-167) | 400 | 0 | 0 | **0** | 0 |
| témoin déterminant (P2-187) | 400 | 0 | 0 | **0** | 0 |
| témoin mot neutre devant CEDEX (P2-200) | 400 | 0 | 0 | **0** | 0 |
| courriers (P2-210) | 3 415 | 0 | 0 | **0** | 0 |
| témoin noms de forme neutre (P2-206) | 400 | 28 | 28 | 28 | 28 |
| **Table complète (34 875 communes)** | | | | | |
| témoin cinq chiffres | 400 | 9 | 9 | 14 | **174** |
| témoin déterminant | 400 | 4 | 4 | 16 | 30 |
| témoin mot neutre devant CEDEX | 400 | 0 | 0 | 0 | **260** |
| courriers | 3 415 | 0 | 0 | 10 | **944** |
| témoin noms de forme neutre | 400 | 400 | 400 | 400 | 400 |

  Avec la table réduite, la tolérance ne coûte rien sur ces témoins : un nom
  de cinq mots à une lettre près n'apparaît pas dans une phrase ordinaire. Les
  28 lignes sont celles de « LES PLACES », déjà là avec le nom exact (c'est le
  coût de la forme D, pas de l'option). Avec la table complète, la tolérance
  rapproche des mots ordinaires de noms courts de communes : jusqu'à 944 lignes
  de courrier sur 3 415 si l'on descend à quatre lettres.
- Ces chiffres sont une **borne haute** (toute étendue que la règle
  produirait, déjà masquée ou non par `Ecluse.redact`) et le texte des témoins
  est mis en capitales pour la mesure, la règle ne vivant que là.
- Coût de réalisation : moyen. Un voisinage de suppressions par nom (261 noms
  de 20 lettres environ : quelques milliers de clés en dur ou calculées une
  fois), une recherche bornée par ligne. Le détecteur reste pur.

### 3. Ne rien faire

- 388 adresses sur 1 007 écritures fautives de 261 communes, soit 0,75 % du
  référentiel exposé **si** le nom est mal écrit. Ce qui reste en clair est la
  fin d'un nom de lieu, jamais un nom de personne ; le code postal est masqué.
- La limite est déjà écrite dans `LIMITES.md` (#432).

## Recommandation

**Faire l'option 1, et l'option 2 seulement sur la table réduite, avec un
seuil de huit lettres.** Raisons : (1) le nom exact seul ne couvre rien des
écritures hors référentiel, alors que « ST » est une écriture postale
ordinaire, pas une faute ; (2) sur la table réduite, les deux options ne
coûtent aucune ligne aux témoins, parce qu'un nom de cinq mots ne se confond
pas avec du texte ; (3) la règle du 13 novembre (« dans le doute, le côté qui
protège ») va dans ce sens tant que le coût mesuré est nul. **Ne pas étendre la
tolérance à la table complète** : c'est elle qui produit les faux positifs, et
c'est une raison de plus de garder la table réduite de #432.

À faire avant de coder l'option 2, parce que la simulation ne le dit pas : un
témoin de faux positifs propre aux noms longs (des phrases en capitales de
cinq mots ou plus derrière un nombre à cinq chiffres), et la mesure réelle
après `resolveOverlaps`.

```bash
bash bench/etat.sh > etat.log 2>&1      # génère les témoins dans bench/flou/

python3 ecritures_hors_referentiel.py genere --seed 42 \
    --out flou/corpus_ecritures_hors_referentiel.jsonl
(cd ../packages/ecluse_redact && dart run bin/run_redact_bench.dart \
    ../../bench/flou/corpus_ecritures_hors_referentiel.jsonl \
    ../../bench/flou/pred_ecritures_hors_referentiel.jsonl)
python3 ecritures_hors_referentiel.py couverture \
    --corpus flou/corpus_ecritures_hors_referentiel.jsonl \
    --pred flou/pred_ecritures_hors_referentiel.jsonl
python3 ecritures_hors_referentiel.py cout \
    flou/corpus_flou_cinq_chiffres.jsonl flou/corpus_flou_determinant.jsonl \
    flou/corpus_flou_commune_neutre.jsonl flou/corpus_flou_neutre_cedex.jsonl \
    flou/corpus_courriers.jsonl                  # puis --lettres-min 4
```
