# P2-121 — Entités floues sur un texte entièrement en MAJUSCULES

Mesure seulement, rien n'est corrigé. 6 novembre 2026, `main` au commit
`83d883f`. Complète P2-117 (texte en minuscules), qui laissait ce cas de
côté.

## Méthode

Corpus flous v2 (graine 42, 400 documents chacun) mis en capitales
(`text.upper()`, longueur vérifiée identique, offsets inchangés). Moteur :
`run_redact_bench.dart` ; score : `score_flou.py`. Commandes : celles de
`agent/specs/P2-117.md`, avec `.upper()` au lieu de `.lower()`.

## Résultats : fuite au caractère

| Type | réaliste d'origine | réaliste MAJUSCULES | adversarial d'origine | adversarial MAJUSCULES |
|---|---:|---:|---:|---:|
| nom | 27,7 % | **35,6 %** | 18,3 % | **23,7 %** |
| établissement | 0 % | **27,2 %** | 0 % | **12,0 %** |
| adresse | 0 % | 0 % | 1,9 % | 1,9 % |
| date de naissance, courriel, téléphone | 0 % | 0 % | 0 % | 0 % |
| **Global** | **7,5 %** | **14,8 %** | **9,3 %** | **13,0 %** |

Corpus témoin en majuscules : **194 faux positifs** (adresse), tous de deux
gabarits : « 70000 EUROS HORS TAXES » et « 75015 POUR L'ANTENNE
PARISIENNE ». En minuscules ou en casse normale, ces mêmes phrases ne
donnent rien (P2-120).

## Ce que cela dit

- Le texte en capitales est **moins grave** que le texte en minuscules
  (global 14,8 % contre 64,2 % avant P2-119/P2-120), mais il double la
  fuite globale et fait apparaître des faux positifs d'adresse.
- **Établissements** : en capitales, le nom qui suit le mot-clé n'est plus
  distingué d'un sigle (« EHPAD MARIE CURIE »).
- **Faux positifs d'adresse** : le filtre « la commune commence par une
  majuscule » (`AdresseDetector`) ne filtre plus rien quand tout est en
  capitales ; « EUROS » ou « POUR » passent pour une commune.
- Aucun avertissement n'est émis pour un texte en capitales.

## Ce que cette mesure ne dit pas

- La part réelle des textes en capitales (copier-coller de formulaires,
  courriers anciens) : inconnue.
- Une seule graine.

## Pour le mainteneur

Tâche proposée P2-122 (`code`) : sur le modèle de P2-120, rendre la casse
ordinaire à un texte **sans aucune minuscule** avant les détecteurs
d'adresse et d'établissement, avec 0 faux positif sur le témoin en
majuscules et des sorties identiques sur les corpus d'origine.

## Après correction (P2-122, 6 novembre 2026)

| Corpus en capitales | adresse | établissement | nom | global |
|---|---|---|---|---|
| réaliste | 0 % → 0 % | 27,2 % → **0 %** | 35,6 % (inchangé) | 14,8 % → **9,7 %** |
| adversarial | 1,9 % → 1,9 % | 12,0 % → **0 %** | 23,7 % (inchangé) | 13,0 % → **11,9 %** |
| témoin (faux positifs) | 194 → **0** | | | |

- `AdresseDetector` : dans un texte sans aucune minuscule, une commune qui
  commence par un mot neutre (`mots_neutres.dart`, partagé avec P2-120) est
  écartée. Le test existant « 12 RUE DES LILAS, 75015 PARIS » reste vert.
- `MinusculesRecapitaliseDetector` traite aussi un texte sans minuscule (mis
  en minuscules puis recapitalisé) pour les établissements ; pas pour les
  adresses (`capitales: false`), déjà lues en capitales.
- En passant : « CEDEX » gardé en capitales et élision en tête de commune
  (« 25250 l'isle-sur-le-doubs ») dans le texte d'ombre ; fuite des adresses
  sur l'adversarial **en minuscules** : 26,6 % → **15,7 %**.
- Un premier essai (`AdresseDetector` muet en capitales) cassait un test
  existant et rendait l'élision quadratique (`cout_blancs_apres_chiffre_test`) :
  abandonné, remesuré.
- Sorties identiques : v3, réaliste, adversarial, témoin, réaliste en
  minuscules et sans ponctuation.

## Après correction des noms (P2-123)

`NomMinusculesDetector` lit aussi un texte sans aucune minuscule, mis en
minuscules (même longueur, valeur relue dans l'original). Fuite des noms en
capitales : réaliste 35,6 % → **2,2 %**, adversarial 23,7 % → **18,7 %** ;
global : réaliste 9,7 % → **0,6 %**, adversarial 11,9 % → **9,5 %**. Témoin
en capitales : 0 faux positif. Autres corpus : sorties identiques.
