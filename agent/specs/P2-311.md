# P2-311 — Références de quatorze chiffres : coût d'un masquage (mesure)

Type `mesure` : **rien n'est corrigé**, `lib/` n'est pas modifié. Question de P2-307 (PR #569) :
faut-il **signaler** (état actuel) ou **masquer** un SIRET de clé juste sans le mot « siret » et une
TVA à clé fausse sans libellé ? Les témoins du dépôt n'en contiennent aucun hors libellé ; le coût
d'un masquage n'était donc pas mesuré. Ajouts de mesure : `bench/generate_corpus_references_14.py`
(corpus), `bench/analyse_references_14.py` (analyse), `bench/mesure_references_14.sh` (≈ 30 s),
`bench/test_references_14.py`.

## Chemin mesuré

**`Ecluse.redact`** (chemin du produit, ce que reçoit le LLM), par
`packages/ecluse_redact/bin/run_gardes_avertissements.dart` : entités et avertissements. Le
masquage est **simulé hors du code produit** : un document serait masqué à tort si sa référence
est lue par le détecteur (quatorze chiffres de Luhn juste, collés ou en groupes — la compaction
retire les blancs entre chiffres ; « FR » + clé + neuf chiffres pour la TVA) sans le mot « siret »
ni libellé de TVA. La simulation est calculée par le script d'analyse à partir des chiffres de
Luhn notés par le générateur, pas à partir des avertissements : les deux doivent coïncider
(contrôle de cohérence : 0 forme en écart).

## Corpus

3 000 documents synthétiques (graine 42, 300 par forme), **sans aucune donnée personnelle** (aucune
entité annotée : tout masquage y est en trop). Chaque nombre est tiré au hasard, jamais copié d'une
source réelle. Une phrase logistique ou administrative par document, trois gabarits par forme.

| Forme | Contenu |
|---|---|
| `suivi_colis`, `commande`, `lot`, `facture` | quatorze chiffres collés, tirés uniformément |
| `horodatage` | AAAAMMJJhhmmss plausible (2019-2026) |
| `groupe_3335` | quatorze chiffres écrits « 3 3 3 5 » (la forme d'un SIRET) |
| `groupe_4442` | quatorze chiffres écrits « 4 4 4 2 » |
| `tva_cle_fausse` | « FR » + clé à deux chiffres fausse + neuf chiffres |
| `tva_cle_lettre` | « FR » + clé à lettre + neuf chiffres |
| `sans_reference` | témoin sans nombre de quatorze chiffres |

## Résultat

Sortie de `bash bench/mesure_references_14.sh` (3 000 documents).

| Forme | Documents | Réf. de Luhn juste | **Masqués à tort si on masquait** | Signalés aujourd'hui (SIRET / TVA) | Masqués aujourd'hui, un type quelconque |
|---|---|---|---|---|---|
| `suivi_colis` | 300 | 31 | **31 (10,3 %)** | 31 / 0 | 0 |
| `commande` | 300 | 24 | **24 (8,0 %)** | 24 / 0 | 0 |
| `lot` | 300 | 25 | **25 (8,3 %)** | 25 / 0 | 0 |
| `facture` | 300 | 28 | **28 (9,3 %)** | 28 / 0 | 0 |
| `horodatage` | 300 | 36 | **36 (12,0 %)** | 36 / 0 | 0 |
| `groupe_3335` | 300 | 42 | **42 (14,0 %)** | 42 / 0 | 300 (adresse 285, RPPS 15) |
| `groupe_4442` | 300 | 20 | **20 (6,7 %)** | 20 / 0 | 31 (téléphone) |
| `tva_cle_fausse` | 300 | – | **300 (100 %)** | 0 / 300 | 35 (RPPS) |
| `tva_cle_lettre` | 300 | – | **300 (100 %)** | 0 / 300 | 25 (téléphone) |
| `sans_reference` | 300 | – | 0 | 0 / 0 | 0 |
| **Total** | 3 000 | 206 | 806 | 206 / 600 | 391 |

- **SIRET sans le mot « siret »** : 206 références sur 2 100 (**9,8 %**) ont une clé de Luhn
  juste, soit un sur dix, comme prévu pour un nombre tiré au hasard. Masquer les quatorze chiffres de
  clé juste sans le mot masquerait donc **un document sur dix** qui porte une référence de quatorze
  chiffres (de 6,7 % à 14,0 % selon la forme, 300 documents par forme : les écarts entre formes sont
  du bruit d'échantillonnage). Le signalement d'aujourd'hui touche **exactement les mêmes 206
  documents** : signaler et masquer ont le même coût en documents, la différence est ce qu'en voit le
  LLM (un avertissement à l'utilisateur, ou une référence illisible).
- **TVA à clé fausse ou à lettre sans libellé** : **600 / 600**. La forme « FR » + deux caractères +
  neuf chiffres n'a aucun garde-fou ici : tout code qui la porte est signalé, donc masqué si on
  masquait. Le coût est proportionnel au nombre de tels codes dans les textes d'un client, pas à un
  taux : sur ce corpus, 100 %.
- **Aujourd'hui déjà, ces références sont partiellement masquées à tort par d'autres détecteurs**
  (hors fiche, constat) : 285 / 300 `groupe_3335` par le détecteur d'adresses (les cinq derniers chiffres sont lus
  comme un code postal, le mot suivant comme une commune) et 15 par le RPPS ; 31 / 300 `groupe_4442` en téléphone ; 35 / 300 TVA à
  clé fausse en RPPS (la clé et le SIREN font onze chiffres, un sur dix passe Luhn) ; 25 / 300 TVA à
  lettre en téléphone. Aucune de ces entités ne couvre la référence en entier : le signalement
  s'ajoute donc, il ne fait pas double emploi.
- **Horodatages** : les 36 horodatages de clé de Luhn juste se lisent tous comme une date et une
  heure valides ; sur 19 736 nombres de quatorze chiffres de Luhn juste tirés uniformément (hors
  corpus, graine fixe), **0** se lisent ainsi. Un filtre « AAAAMMJJhhmmss valide n'est pas un
  SIRET » retirerait 36 / 206 signalements (17 %) de ce corpus pour une perte attendue quasi nulle
  sur de vrais SIRET (la plupart commencent par un SIREN qui ne ressemble pas à une année).

## Ce que la mesure ne dit pas

- **La fréquence réelle** de ces références dans les textes d'un client est inconnue : les 9,8 % sont
  le taux de Luhn d'un nombre aléatoire, pas une part des documents. Le corpus force une référence
  par document.
- **Le bénéfice** d'un masquage (un SIRET d'entrepreneur individuel sans le mot « siret », qui
  identifie une personne) n'est pas mesuré : aucun témoin du dépôt n'en contient. La sonde de P2-303
  (80 / 80 signalés) montre que le signalement fonctionne, pas que le cas est fréquent.
- Les nombres sont uniformes ; de vraies références ont des structures (préfixes, dates, sommes de
  contrôle propres) qui changent le taux de Luhn. Les horodatages sont à 12 % ici, pas à 10 %, sans
  qu'on puisse l'attribuer à autre chose qu'à l'échantillon.
- Un seul libellé de TVA et un seul mot de SIRET sont gérés par le code ; les variantes (« n° de TVA
  intracommunautaire » écrit autrement, « SIREN ») ne sont pas explorées.
- Le texte des phrases est court et très régulier (trois gabarits par forme) : l'effet du contexte
  (fenêtre de 40 caractères autour du mot) n'est pas sondé.

## Recommandation chiffrée, pour la décision du mainteneur

1. **SIRET sans le mot « siret » : garder le signalement, ne pas masquer.** Masquer coûterait 9,8 %
   des documents qui portent une référence de quatorze chiffres (par exemple 98 sur 1 000 documents
   logistiques si tous en portent une), illisibles pour le LLM, sans aucun témoin d'un SIRET
   d'entrepreneur individuel écrit sans le mot. Le signalement coûte les mêmes documents mais ne
   change rien à ce que le LLM lit. À revoir si un client montre ce cas.
2. **Réduire le bruit du signalement plutôt que d'élargir le masquage** : ignorer un nombre de
   quatorze chiffres qui se lit comme un horodatage valide retirerait 36 / 206 signalements (17 %)
   de ce corpus (proposition de tâche `code`, voir le compte rendu de session).
3. **TVA sans libellé : garder le signalement, ne pas masquer.** 600 / 600 : aucune règle de forme ne
   départage un numéro de TVA d'un code article ; masquer reviendrait à masquer tout « FR » + onze
   caractères. Le signalement est bruyant (chaque document concerné le porte) : à ne durcir qu'avec
   une mesure sur des textes de client.
4. **Séparément (constat, pas une décision de cette tâche)** : le détecteur d'adresses masque 285 / 300
   références « 3 3 3 5 » en partie, et le téléphone ou le RPPS d'autres formes. Une tâche `mesure`
   dédiée peut en chiffrer la gêne.
