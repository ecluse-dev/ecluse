# P2-157 — Adresses : les 1,9 % de fuite du corpus flou adversarial

Tâche de type `mesure` : rien n'est corrigé. Données synthétiques seulement.

## 1. Ce qui est mesuré

Corpus `bench/flou/corpus_flou_adversarial.jsonl` (400 documents, graine 42,
`bench/generate_corpus_flou.py`), prédictions de **`Ecluse.redact`** (chemin du
produit : `run_redact_bench.dart` appelle `Ecluse.redact`, option
`prenomsInsee` désactivée). Une adresse annotée « fuit » pour chaque caractère
qu'aucune entité prédite (de n'importe quel type) ne recouvre. Reproduit par
`python3 bench/analyse_fuite_adresses.py` après `bash bench/etat.sh`.

| | Annotations | Caractères |
|---|---:|---:|
| Adresses annotées | 155 | 5 627 |
| dont avec « CEDEX » | 53 | — |
| **Caractères en clair** | **53 adresses touchées** | **106 = 1,88 %** |

Le 1,9 % de `bench/ETAT.md` est retrouvé exactement.

## 2. La forme manquée : une seule

Les 106 caractères sont **tous** les deux caractères « ␣9 » de
« … 70000 VESOUL CEDEX 9 » : le mot CEDEX et la commune sont masqués, le
numéro de distribution qui les suit reste en clair, 53 fois sur 53. Aucune
autre forme d'adresse n'est manquée : numéro, voie, code postal, commune sont
couverts à 100 % dans ce corpus.

Cause : le motif d'adresse s'arrête à la commune ; « Cedex 03 (le suffixe reste
en clair, sans valeur identifiante) » est **déjà documenté dans `LIMITES.md`**
(P2-49). La mesure confirme que c'est la seule fuite d'adresse du corpus.

Limite de ce que le corpus montre : le générateur écrit toujours « CEDEX 9 »
(`generate_corpus_flou.py`, une seule valeur), donc 53 cas identiques ne
mesurent pas la variété réelle (« CEDEX 01 », « Cedex 15 », « CEDEX » seul).

Le réaliste à 60 colonnes : mon décompte brut (2,47 %) diffère du 1,3 % de
`ETAT.md` parce qu'il **inclut les 2 documents refusés** (exclus du calcul de
référence) ; la forme manquée est le mot de commune coupé par la fin de ligne
(« DAMPIERRE SUR⏎SALON »). Explication probable, non vérifiée document par
document. C'est le sujet de P2-153/P2-162, pas de celui-ci.

## 4. Risque

Un numéro de distribution CEDEX (1 à 2 chiffres) est un code postal de
routage d'organisation ; avec commune et voie masquées, il ne localise rien et
n'identifie aucune personne. Le risque de ré-identification est très faible ;
l'effet est surtout sur la **mesure** (1,9 % qui disparaîtrait du tableau) et
sur la cohérence du texte envoyé au LLM (« [ADRESSE_1] 9 »).

## 5. Ce qui reste incertain

- Aucune adresse réelle : la fréquence de « CEDEX » dans de vrais comptes
  rendus n'est pas connue ; ici 34 % des adresses (53/155) par construction.
- Pas de sonde hors corpus sur « CEDEX » sans numéro ou « Cedex 03 » : non
  rejouée (la fiche demande l'analyse du corpus).
- Le motif « CEDEX » est aussi touché par les PR ouvertes P2-181 et P2-184
  (communes longues devant « CEDEX », table des communes) ; non relues ici,
  l'effet sur ce chiffre est à rejouer après leur fusion.

## 6. Pour le mainteneur

Créer, s'il le souhaite, une tâche `code` : test d'abord (« CEDEX 9 », « Cedex
03 », « CEDEX » seul, « cedex 15 ») avec contre-exemples (« cedex » dans une
phrase sans code postal), correction du motif d'adresse pour couvrir le
numéro, mesure avant/après : fuite adresses adversarial 1,9 % → 0 %,
précision inchangée, témoins à 0 faux positif. Alternative : accepter la
limite documentée et retirer ces 2 caractères du compte.
