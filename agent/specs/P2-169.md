# P2-169 — Audit des voies de fuite (novembre 2026)

Type : mesure. Aucun fichier de `lib/` n'est modifié. Méthode : skill
« revue des voies de fuite » (grep des `throw` interpolés, des `toString`,
des `print`/`stderr`/`developer.log`, des sérialisations), lecture des sites
trouvés, puis sonde jetable (non versionnée) avec des entrées synthétiques.
Les limites déjà documentées (`LIMITES.md` § 8, `agent/specs/P1-08-audit.md`
§ 3) ne sont pas répétées.

## 2. Voies fautives

Toutes dans `ecluse_reid` (et une dans `ecluse_reference`), c'est-à-dire pour
une application qui appelle ces types **directement** (journal d'erreurs,
`print` de débogage, sérialisation de la trace). Le chemin `Ecluse.redact`
ne les expose pas (§ 1, `risque.dart`).

### F1 — `Qi.toString` (gravité moyenne)

`packages/ecluse_reid/lib/src/qi.dart:33` :
`'Qi(${type.name}, $value, niveau $level)'`.
Entrée : `Qi(QiType.lieu, 'Vesoul-synth')`. Sortie :
`Qi(lieu, Vesoul-synth, niveau 0)`. La valeur d'un quasi-identifiant
(commune, âge exact, profession) sort telle quelle dès qu'un `Qi` est
interpolé dans un message, un log ou une trace de pile d'assertion.

Tâche `code` proposée : `toString` sans `value` (type, niveau, longueur
éventuelle). Test : `expect(Qi(QiType.lieu, 'Vesoul-synth').toString(),
isNot(contains('Vesoul-synth')))`.

### F2 — `ReidTrace.toAuditMap`, clé `qisInitiaux` (gravité moyenne)

`packages/ecluse_reid/lib/src/reid_trace.dart:94` : `qi.toString()`, donc F1
écrit les valeurs dans une structure présentée comme « preuve d'audit AIPD,
JSON-sérialisable ». Aucun test existant ne couvre `qisInitiaux`. Entrée :
une trace construite avec un QI lieu et un QI âge synthétiques ; sortie :
`qisInitiaux: ['Qi(lieu, Vesoul-synth, niveau 0)', …]`. Le reste de la carte
(types, niveaux, F, bandes) est sain.

Tâche `code` proposée : n'émettre que `type.name` et `level` par QI. Test :
la carte sérialisée en JSON ne contient aucune valeur de QI.

### F3 — `PathologieMention.toString` (gravité haute)

`packages/ecluse_reid/lib/src/pathologie_extraction.dart:75` :
`'PathologieMention($start-$end « $text » → …)'`. Entrée :
`extrairePathologies('Madame X a une mucoviscidose.')` ; sortie :
`PathologieMention(15-28 « mucoviscidose » → mucoviscidose, table)`. Le texte
extrait (une donnée de santé rattachée à une personne) sort dans tout log.
C'est un extrait du texte, donc gravité haute selon l'échelle de la revue.
Distinction à garder : `risque.dart` (`_limitePathologies`) cite volontairement
« `${m.text}` » dans le rapport rendu à l'application, car la limite doit dire
à l'utilisateur ce qui reste en clair ; ce n'est pas la voie signalée ici.

Tâche `code` proposée : `toString` avec bornes, catégorie, source et
rattachement, sans `text`. Test : `isNot(contains('mucoviscidose'))`.

### F4 — `ArgumentError` de `ecluse_reid` avec valeur de QI (gravité moyenne)

`estimator.dart:208, 236` (`age: valeur "${ageQi.value}" illisible`,
`age: tranche "${ageQi.value}" invalide`), `lieu_population.dart:55`
(`lieu: commune "${lieu.value}" inconnue`). Entrée : un QI âge de valeur
`47 ans synth`, évalué hors `Ecluse.redact` ; message :
`Invalid argument(s): age: valeur "47 ans synth" illisible.` Reproduit en
construisant le message à l'identique ; le chemin `Ecluse.redact` le masque
(§ 1). `estimator.dart:228` (`$exact`) est dans le même cas pour l'âge exact.

Tâche `code` proposée : messages à motif fixe (« âge illisible », « commune
inconnue »), niveau et type seulement. Test : un QI synthétique invalide
lève une erreur dont `toString()` ne contient pas la valeur.

### F5 — `GeoHierarchy.populationOfDep` (gravité basse)

`packages/ecluse_reference/lib/src/geo_hierarchy.dart:166` et suivantes :
`département "$dep" inconnu` / `population du département "$dep" incomplète`.
`dep` est un code à deux ou trois caractères, souvent déduit d'une commune
du texte : métadonnée géographique grossière. À corriger avec F4 pour la
cohérence, pas séparément.

### Hors décompte

`BirthDate.toString` (`birth_dates.dart:36`) écrit année-mois-jour : une date
de naissance exacte, **gravité moyenne** (quasi-identifiant fort), reproduite
(`BirthDate(1951-3-14)`). Même correctif et même test que F1. `Generalization.toString`
(`generalizer.dart:36`) interpole `$from` et `$to`, des `Qi` : sortie
`Generalization(Qi(…valeur…) -> Qi(…), F: …)`, donc F1 se propage ; il se
règle avec F1.

## 3. Propositions de tâches `code`

Une par voie fautive, regroupables en une seule PR de `ecluse_reid` :

1. P2-A : `Qi.toString`, `BirthDate.toString`, `Generalization.toString` sans
   valeur (F1, hors décompte) ; test de non-fuite par type.
2. P2-B : `ReidTrace.toAuditMap` sans valeur (F2) ; test sur le JSON complet.
3. P2-C : `PathologieMention.toString` sans `text` (F3).
4. P2-D : messages d'`ArgumentError` à motif fixe dans `estimator`,
   `lieu_population` et `geo_hierarchy` (F4, F5).

Chaque tâche commence par le test qui montre le défaut (règle 5).

## 4. Non vérifié

- Le comportement réel d'une application cliente (ce qu'elle journalise ou
  envoie à un outil de suivi d'erreurs).
- La sonde n'a pas appelé l'estimateur sur une référence chargée : les
  messages de F4 sont reproduits par construction du message, pas par un
  appel de bout en bout.
- `ecluse_ner` et les branches non fusionnées ne sont pas couverts.
- Les `reason:` et les noms de tests n'ont pas été relus.
