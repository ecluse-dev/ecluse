# P2-156 — Montée de `pdf_cos`, `pdf_document`, `pdf_graphics` (10.0.0 → 15.0.0)

Tâche de type `mesure` : rien n'est corrigé sur `main`. Le changement de
`pubspec.yaml` a été fait sur une branche jetable, **n'est pas dans cette PR**
et la décision de monter revient au mainteneur (DECISIONS.md « PDF » : version
fixée, relecture avant adoption).

Données synthétiques seulement : `bench/pdf/` (18 PDF fabriqués par
`bench/generate_pdfs.py`, graine 42).

## 1. Ce qui a été fait

Sur une branche partie de `main` (commit `fabdb80`), les trois paquets ont
été portés ensemble de `10.0.0` à `15.0.0` (versions fixées, comme
aujourd'hui) dans `packages/ecluse_ingest/pubspec.yaml`, puis
`melos bootstrap`. Dart 3.14.0 dans cet environnement.

Résolution : `pdf_cos`, `pdf_document` et `pdf_graphics` passent à 15.0.0.
Une seule dépendance transitive **nouvelle** : `characters 1.4.1`
(demandée par `pdf_document` 15, licence BSD-3 de l'équipe Dart ; absente
de 10.0.0). `bidi` (2.0.13) et `image` (4.12.0) sont inchangés. Les
trois paquets exigent toujours `sdk: ^3.5.0` (comme avant).

de texte seule), pas `Ecluse.redact`.

## 3. Notes de version lues (CHANGELOG des sources 15.0.0 et guide de migration)

- `pdf_graphics` 11 → 15 : rendu (rectangles minces, images masquées,
  orientation d'images pivotées, pointillés), alignement des bandes de
  sélection ; rien sur l'extraction de texte ni sur la détection de pages
  numérisées utilisée par l'adaptateur.
- `pdf_cos` 11 → 15 : signatures CMS, RSA/ECDSA ; 15.0.0 renvoie au guide de
  migration, qui ne parle que de l'édition de texte en ligne
  (`PdfEditingController`) et de la rédaction (`removeHiddenInformation`).
- `pdf_document` 11 → 15 : 11.0.0 est marqué **BREAKING** (une nouvelle
  valeur d'énumération d'annotation, `reflowTable` ; ne concerne que les
  `switch` exhaustifs sur ce type, ce que l'adaptateur n'écrit pas) ;
  15.0.0 change l'application des rédactions (métadonnées, pièces jointes,
  JavaScript retirés par défaut) : fonctionnalité d'édition que
  `ecluse_ingest` n'utilise pas.
- L'adaptateur (`lib/src/pdf/pdf_graphics_source.dart`) n'appelle que
  `PdfDocument.open`, `cos.isEncrypted`, `catalog`, `pageCount`,
  `page(i).annotations` et l'extraction de texte ; `CosPasswordException`
  pour le chiffrement. Aucune de ces API n'est citée comme modifiée.
- Un seul mainteneur et une cadence de versions majeures très rapide
  (5 majeures de plus : 11 à 15 depuis la fixation de 10.0.0) : le risque
  qui motivait la version fixée est confirmé, pas levé.

## 4. Effort estimé

Aucun changement de code : modifier les trois lignes de `pubspec.yaml`,
`melos bootstrap`, rejouer. Une relecture de l'arbre transitif reste due
(`characters` nouveau, BSD-3 ; les dépendances de `bidi` ne sont toujours pas
auditées, DECISIONS.md « PDF »).

## 5. Ce qui n'a pas été vérifié

- Seuls les 18 PDF synthétiques ont été rejoués : ils couvrent texte,
  colonnes, scan, mixte, chiffré, JavaScript, annotations, xref cassé,
  page perdue, mais pas de PDF produits par des logiciels réels
  (règle 1 : aucune donnée réelle).
- Non mesurés : mémoire et temps d'extraction à plein plafond (50 Mo,
  200 pages ; le jeu `--with-oversize` n'a pas été rejoué), ni les versions
  intermédiaires 11 à 14 (un saut direct 10 → 15 a été essayé).
- Les notes de version sont celles livrées avec les sources ; le dépôt
  GitHub du paquet n'a été lu que pour le guide de migration 15.0.0.
- Aucun contenu de PDF n'est cité dans un message d'erreur : les tests de
  refus du paquet (code seul, message générique) passent à l'identique.

## 6. Décision qui revient au mainteneur

Monter ou non en 15.0.0. Le contrôle ne montre aucune régression sur le
jeu synthétique ; la décision porte sur la confiance dans le paquet (mainteneur
unique, majeures rapides) et sur le gain attendu, qu'aucune mesure ici ne
chiffre (les changements 11 à 15 ne touchent pas l'extraction de texte).
