# P2-156 — Montée de `pdf_cos`, `pdf_document`, `pdf_graphics` (10.0.0 → 15.0.0 et 16.0.0)

Type `mesure` : rien n'est corrigé et **le changement de `pubspec.yaml` n'est
pas dans la PR**. Le mainteneur décide de la montée.

Mesuré le 14 novembre 2026 sur `main` (`fabdb80`), Dart de la session cloud,
trois paquets montés ensemble (la suite est versionnée d'un bloc).

## Constat de départ

La fiche annonce « dernière 15.0.0 ». Au jour de la mesure, pub.dev publie
**16.0.0 (13 novembre 2026)** ; 15.0.0 date du 5 novembre, 10.0.0 du
18 octobre. Quatre versions majeures en un mois, dont 11.0.0 (cassante pour
l'API d'annotation) : la cadence signalée dans `packages/ecluse_ingest/pubspec.yaml`
se confirme. Les deux versions ont donc été essayées.

## Ce qui casse : rien, sur ce qui est mesuré

| Contrôle | 10.0.0 (actuelle) | 15.0.0 | 16.0.0 |
|---|---|---|---|
| `melos bootstrap` | ok | ok | ok |
| `melos run analyze` (`--fatal-infos`, 9 paquets) | ok | ok | ok |
| `melos run test`, `ecluse_ingest` | 158 verts | 158 verts | 158 verts |
| `melos run test`, tous paquets | verts | verts | verts |
| `generate_pdfs.py` : sortie identique à `bench/pdf` | oui | — | — |

Plus fort que les tests : le texte extrait par `ingestFile` (texte, avertissements
et motifs de refus) a été comparé **octet pour octet** entre 10.0.0 et 16.0.0
sur les 18 PDF synthétiques de `bench/pdf` : **identique** (même script jetable
lancé deux fois, non versionné). Motifs de refus inchangés : `chiffre`,
`partiellement_numerise`, `sans_texte`, `texte_illisible`, `plafond_pages`,
`malforme`.

**Chemin mesuré** : l'adaptateur d'ingestion PDF seul (`ingestFile`) sur des PDF
synthétiques. Ce n'est ni `Ecluse.redact` ni un PDF réel.

## Ce qui change dans l'arbre de dépendances

Contraintes lues sur l'API pub.dev (SDK `^3.5.0` partout, comme à présent) :

- `pdf_document` 15 et 16 ajoutent **`characters ^1.4.1`** (paquet de l'équipe
  Dart, déjà dans le SDK Flutter ; **non audité ici**, licence à confirmer dans
  `DATA_SOURCES.md`/`pubspec.yaml` si la montée est retenue).
- `pdf_cos` 16 exige `archive ^4.6.0` (le dépôt déclare `^4.0.2` : compatible,
  la résolution prend 4.6+).
- `crypto` passe de `^3.0.0` à `^3.0.8`. `bidi` et `image` inchangés.

## Notes de version lues (changelog pub.dev de `pdf_document`)

- 11.0.0 : **cassante** (`PdfAnnotationResizeBehavior.reflowTable`) ; ne
  concerne que l'édition d'annotations, que l'adaptateur n'utilise pas.
- 12.0.0, 13.0.0, 14.0.0 : annotations, formulaires FDF/XFDF, signatures PAdES
  distantes ; « pas de changement d'API publique » pour 14.0.0.
- 15.0.0 : refonte de la **rédaction** (pixels d'images, formulaires, texte
  caché, métadonnées et pièces jointes retirés par défaut). 16.0.0 : liens
  conservés dans les instantanés, remplacement de page raster, rédaction
  « mot entier » par défaut.

Tout cela touche l'édition et la rédaction de PDF, pas la lecture de texte
qu'Écluse utilise. Aucune mention d'un changement de l'extraction de texte, du
comptage de pages ni de la gestion des fichiers malformés ; la mesure ci-dessus
ne montre pas non plus de différence.

## Effort estimé

Faible pour la montée elle-même : trois lignes de `pubspec.yaml`, aucune
modification de code. Le travail est de relecture : `characters` (licence,
audit), et le point suivant.

## Ce qui n'a pas été vérifié

- **Aucun PDF réel** (règle 1 : synthétiques seulement). Les 18 PDF
  synthétiques ne couvrent pas les polices incorporées variées, les PDF
  produits par les logiciels de planning ou les formulaires réels ; une
  différence d'extraction sur ces contenus ne serait pas vue ici.
- Coût (temps, mémoire) de l'extraction non mesuré ; le plafond de 250 pages
  est testé et refusé comme avant.
- Version intermédiaire 11.0.0 à 14.0.0 non essayée une à une.
- Le code source des paquets n'a pas été relu ; seuls le changelog et les
  contraintes de pub.dev l'ont été.

## Décisions qui reviennent au mainteneur

1. Monter ou non (la fixation exacte de `DECISIONS.md` « PDF » demande une
   relecture ; cette mesure en est la base). Recommandation : la version
   **16.0.0** plutôt que 15.0.0, qui date de huit jours et a déjà un successeur.
2. Accepter `characters` comme dépendance transitive nouvelle.
3. Rejouer ce rapport à chaque montée (cadence de versions majeures
   rapide).
